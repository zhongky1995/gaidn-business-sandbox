# GAIDN · 企业AI组织化沙盘

从一项真实工作出发，看看已有判断如何留下来、被团队和AI继承。单文件HTML，核心诊断与图片在浏览器本机完成，无需在线模型API。

[GitHub Pages](https://zhongky1995.github.io/gaidn-business-sandbox/) · [妙搭公开版](https://ycntefqc810o.feishuapp.com/app/app_17g1ae49dbx)

## 使用

1. 复制网页提示词或下载SKILL.md，发给常用AI；介绍业务和想改善的一项工作，AI按需要补问。
2. 将完整JSON参数导入网页，核对选定工作、实际事例、记录与推进安排。细节可以展开修改。
3. 生成组织AI化画像，点图查看依据；保存PNG或参数，之后可重新导入。

没有可用资料、未安排负责人、暂无积累都可以如实填写，会匹配准备或探索路线。必需事实应由提示词先确认；核对页也提供补问清单和草稿下载。旧schema 1.0可以导入，原参数完整保留在legacy_parameters；新增事实需补充，不从旧资料自动判定成熟度。刷新前先保存参数，网页不自动保存草稿。

## 模型与边界

v2.0.0使用schema 2.0。方法参考老谭的四档推进路径、L0–L5判断力成熟度及准则四要素；四类知识为其文章认可的转述。具体匹配、标题、准备段和曲线为GAIDN产品设计，不是经过企业样本验证的量表。

只判断本次选定的场景，规模与用了多少工具不决定成熟度。关键判断可能在人脑、普通记录、明确准则、AI实际调用或持续修订中；全公司评级和L5认证不在承诺内。六种经营类型作为背景，不决定组织状态。

每份可生成画像均有一条条件情景曲线，展示相对准备、使用与复用节奏，不预测日期、营收、ROI或增长率。真实经营判断与最终采用由有权负责人复核。示例企业均为虚构，不代表已交付客户案例。

## 构建和检查

```sh
python3 publish.py
node --test tests/model.test.cjs tests/legacy.test.cjs tests/analytics.test.cjs
```

app为可维护源文件，dist为单文件产物，docs为GitHub Pages发布目录。legacy-model只用于旧合同校验/迁移及原曲线函数；当前诊断逻辑在model.js。妙搭使用独立来源配置后构建发布，两站不自动同步。

GA4仅在配置的正式域名和路径启用，使用白名单操作事件；不发送企业名称、业务文字、参数或图片内容。广告个性化和Google signals关闭。技术测试不等于真实经营效果或转化数据。
