# GAIDN · 企业AI经营沙盘

从一项真实工作和具体事例，看看已有本事怎样借助AI用到更多次业务。纯前端单文件，诊断、参数与图片在本机处理，无需在线模型API。

[GitHub Pages](https://zhongky1995.github.io/gaidn-business-sandbox/) · [妙搭公开版](https://ycntefqc810o.feishu.link/app/app_17g1ae49dbx)

## 使用

1. 复制完整提示词或下载SKILL.md，发给常用AI；已有介绍和脱敏事例可一起提供。
2. AI确认本次工作、实际依据、希望支持的对象和起步条件，返回完整JSON。
3. 导入网页，核对重点后生成；按需展开细节、修改、查看依据，保存PNG或参数。

明确暂无积累、没有可用资料、未安排负责人都可如实回答，会得到探索或准备路线。必需事实由提示词前置确认，网页在出图前检查缺项与冲突，不在最终海报留下空白。

schema1.0、2.0和3.0参数可导入，完整原对象保存在previous_parameters；1/2旧参数补机会与关系事实，3.0旧参数仅补业务结果；不从旧类型/等级猜测。下载草稿保留原参数。网页不自动保存业务草稿，刷新或更新前请先下载参数。

## v3.1.0的统一判断

**具体优势 → 放大方式 → 当前起点 → AI动作与人工分工 → 诊断图形、三步路径及曲线。**

六种主机制分别采用不同关系结构：产品知识共用（共用源与回流）、流程衔接（任务接力链）、专家经验传承（从经验持有者到使用者）、项目经验复用（旧项目与新项目）、供需匹配（双侧条件连接）、多方协作（共同任务网络）。节点来自本次参数中的岗位、资料、步骤或项目，不从行业和人数直接指定。实线为已有描述，虚线为建议建立的支持关系，不能当作已实现结果。无可靠积累另有探索结构。

起点参考老谭文章中的六级状态、准则四要素；分工参考四档组织推进思路，并按本次实际协作单元调整。六级只针对选定工作，不是全公司评级；用了Agent不代表标准已经明确，修订闭环仍有人负责。

曲线现在回答“AI化之后，这项业务结果可能以什么节奏改善”。每份参数必须包含outcome：一个具体业务指标、增加或减少更好、当前做法及测量状态、AI改善设想、比较办法。准备工时减少就向下画；同样人时的合格产出增加才向上画。横轴为实施阶段，与上方三步路径一致。未统一测量是有效答案，不当作0；探索用水平虚线表示改善待验证。

变化节奏仍独立匹配：标准、资料与复核可用且重复任务可先试用；缺少条件先准备再验证；有可检查样板并分环节推广则分段出现；已有使用基础则逐次改善。四种形态共用相同的示意终点，不用高度暗示哪类收益更大；探索不预设正向改善。展示当前做法、AI可能改变结果的原因与同类任务比较办法，计入人工复核和返工。

六类机会结构、匹配、标题和曲线为GAIDN产品设计，不是作者原有测评工具或经企业样本校准的量表。虚线仅示意条件成立后的改善节奏，无数值刻度，不预测日期、营收、ROI、改善比例或增长率。示例均为虚构，不能当作客户案例；最终采用与例外由有权负责人复核。

旧3.0保留已确认的机会事实，仅补新业务结果；旧1/2仍补新版机会事实。previous_parameters保留原始完整对象，不从旧等级猜测业务指标。

## 构建和维护

```sh
python3 publish.py
node --test tests/model.test.cjs tests/legacy.test.cjs tests/analytics.test.cjs
```

app为源文件，dist为单文件产物，docs为GitHub Pages目录。model.js为v3诊断；poster.js负责六种结构的布局、曲线及同源PNG；skill.txt为完整提示词；examples.js为十二个虚构案例。v2-model.js、legacy-model.js仅用于旧合同校验、兼容及底层阶段参考，v3不再复用旧曲线函数。

妙搭保留独立analytics-config.json后构建，检查体积，再复用原app_id发布；GitHub和妙搭需要分别同步。公开发布目录只放index.html。

GA4仅在配置的正式域名与路径启用，沿用白名单操作事件，不发送企业名称、案例、类型、参数或图形内容；广告个性化和Google signals关闭。技术验证不能证明真实企业的理解、分享意愿或经营效果。
