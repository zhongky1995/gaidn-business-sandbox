# GAIDN · 企业 AI 经营沙盘

从一项实际工作出发，看看已有本事怎样借助 AI 用到下一次业务。v4.0.0 / schema4.0，纯前端单文件，无模型 API、数据库或登录。

[GitHub Pages](https://zhongky1995.github.io/gaidn-business-sandbox/) · [妙搭公开版](https://ycntefqc810o.feishu.link/app/app_17g1ae49dbx)

## 使用

1. 复制提示词或下载 SKILL.md，连同已有业务介绍和脱敏事例，发给常用 AI。
2. AI提出主要使用关系和观察模型，前置确认事实、固定指标及相应条件，输出一份参数。
3. 粘贴或导入文件，核对后生成。漏项可在页面补齐，也可直接填写；可修改、查依据、下载 PNG 与参数。

当前标签页自动保留核对草稿；下载草稿可跨设备续接。错误输入不会覆盖原参数。1.0/2.0/3.0/3.1原对象完整保留为previous_parameters，可识别事实带入新版，其余本页补齐；原业务目标单独保留，新模型需明确选择，不从旧指标默选曲线。未知保持待确认，明确没有积累或尚未安排复核也可如实填写。

## 两个独立判断

**已有本事怎样用**：资料共用（资料库与服务环节）、任务接力（编号步骤链）、经验传承（判断条件分叉树）、项目复用（旧项目/模块/新项目及差异核对）、资源匹配（双侧筛选门及人工确认）、协作联动（责任泳道与共同交接记录）。节点取自本次真实来源和使用对象。暂无经验时先验证一次，不宣称已有优势。

**这次观察什么**：四套完整固定模型绑定指标、形态、三步与解释；参数不接受自由坐标、斜率、轴名、增长率或收益。

| 固定模型 | 纵轴 | 形态与前提 |
| --- | --- | --- |
| 重复工作提效 | 完成一次合格任务的总工时 | 先降后趋缓；重复任务、标准/资料/复核就绪，尚未充分工作流化 |
| 经验沉淀复用 | 每次同类任务的总工时，含整理与复核 | 先投入上升，复用成立后可能下降；有真实经验，准备不足先补齐 |
| 持续纠错改进 | 同等任务量下的返工次数 | 逐步下降示意；已有AI使用、实际错误修订和人工复核 |
| 样板逐步推广 | 已通过试用验收的业务场景数 | 逐级上升；已有通过检查的样板、明确逐场景计划，条件就绪 |

四套均不适用时，用“先做一次验证”的水平虚线表示待验证；它不是第五套改善承诺。曲线是条件情景，无数值刻度；线高、斜率和台阶不代表测量值。推广只说明经过验收的范围，不表示工时、营收或利润增长。

参考经验沉淀、标准、人工复核与反馈改进的组织AI化思路；六类关系、选型、标题和曲线为 GAIDN 产品设计，不是老谭原有测评工具或企业样本校准量表。不再在快速诊断中给全公司或单场景硬评等级。示例均为虚构。

## 维护

```sh
python3 publish.py
node --test tests/*.test.cjs
```

app是源文件，dist是独立产物，docs供GitHub Pages发布。model.js是v4参数、校验、固定模型与关系结构；poster.js用同一SVG生成页面与PNG；ui.js负责导入、就地补齐、草稿和导出；skill.txt是提示词；examples.js含9个虚构示例。v3-model.js、v2-model.js、legacy-model.js仅服务旧参数读取及回归，不参与新版曲线决策。

妙搭副本保留自己的analytics-config.json再构建，先检查HTML、压缩包和总量，复用既有app_id发布。两个平台须分别发布。

GA4沿用正式域名及白名单操作事件，不发送企业名称、业务、参数、模型、图形、指标或图片内容；本地调试不启用统计。技术验证不替代真实老板的理解、分享意愿、外部模型提取稳定性或经营效果验证。
